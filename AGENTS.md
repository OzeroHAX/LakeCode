# Подход к работе над LakeCode

## Объём изменений

- Делать только то, что запрошено. Не добавлять функции, абстракции, зависимости или рефакторинг «заодно».
- Для текущего UI использовать моки. Не подключать логику кодингового агента без отдельного запроса.
- Разделять UI на отдельные компоненты, а собирать их в `LakeCode.Cli/Program.cs`.
- Сохранять мои изменения в файлах и подстраиваться под них.

## Изучение проекта

- Не искать существующий код и не использовать индексатор, пока я не попрошу: проект начат с пустой кодовой базы.
- Читать конкретные файлы, необходимые для задачи; не проводить широкий аудит проекта.
- Использовать LSP для работы с символами и проверки диагностики.

## Проверка

- Не создавать и не запускать тесты.
- Не запускать приложение, тесты, форматтеры и другие проверки через команды, кроме сборки проекта. Я проверяю приложение сам.
- В конце любой правки перед финальным ответом обязательно выполнить сборку проекта командой `dotnet build LakeCode.Cli/LakeCode.Cli.csproj` из корня репозитория. Ошибки сборки, вызванные правкой, исправить и повторить сборку; в финальном ответе сообщить фактический результат. Если сборка заблокирована окружением, явно указать причину и не утверждать, что компиляция проверена.
- Допустима дополнительная проверка через LSP. Если сервер не работает, честно сообщать об этом.
- Пришедшую позже диагностику LSP учитывать и исправлять ошибки, не запуская приложение.
- Скриншоты и мои сообщения о поведении использовать как основу для дальнейших изменений.

## Взаимодействие

- По ясному запросу сразу вносить изменения, без лишних подтверждений.
- Если область изменения неоднозначна, задавать короткий конкретный вопрос.
- Кратко сообщать, что изменено и что действительно проверено.
- Не выдавать предполагаемый внешний вид или поведение за результат запуска.

## База агента

- Для базы кодингового агента использовать Microsoft Agent Framework (MAF).
- Базовая зависимость: `Microsoft.Agents.AI` версии `1.24.0` в `LakeCode.Cli/LakeCode.Cli.csproj`.
- Основа агента находится в `LakeCode.Cli/Agent/AgentLoop.cs`: MAF с адаптером `Microsoft.Agents.AI.OpenAI` версии `1.24.0`, OpenAI Responses API, endpoint `https://api.wikivibe.ru/v1`. Модель и уровень рассуждения задаются для каждого запроса; начальный выбор — `gpt-6-luna` и `medium`.
- Каталог моделей и их возможностей находится в `LakeCode.Cli/Agent/ModelCatalog.cs`, описание модели — в `LakeCode.Cli/Agent/ModelInfo.cs`. Namespace файлов агента: `LakeCode.Cli.Agent`.
- Ключ получать из переменной окружения `WIKIVIBE_API_KEY`; не хранить ключи в исходниках. `new AgentLoop()` создаёт агент, `RunAsync(message, model, reasoningEffort, cancellationToken)` возвращает поток `AgentResponseUpdate`. Один экземпляр хранит одну сессию; запросы выполнять последовательно и полностью читать поток ответа. Уровень передаётся через Responses `ReasoningOptions`, включая строковые значения `xhigh` и `max`.
- UI подключён к агенту через `ChatController`. `ModelStore` хранит модель и уровень рассуждения; Shift+Tab в главном окне переключает поддерживаемые моделью уровни. Настройки фиксируются при отправке, изменения во время генерации действуют на следующий запрос. Футер наблюдает сторы; `StatisticsStore` сохраняет последний usage вместе с моделью запроса. Инструменты пока не подключены. Ошибки провайдера и отмена передаются вызывающему коду.
- TPS в футере вычисляется после успешного завершения потока: `OutputTokenCount / секунды от первого непустого TextReasoningContent или TextContent до завершения`. Reasoning уже входит в выходные токены и отдельно не прибавляется. Пока идёт запрос, сохраняется предыдущий TPS; без usage или наблюдаемого первого токена отображается `— tok/s`. Если провайдер не отдаёт reasoning, отсчёт начинается с первого текстового фрагмента ответа.
- Для работы с MAF читать `.agents/skills/microsoft-agent-framework/SKILL.md` и его `references/dotnet.md`; для поиска актуальной официальной документации использовать `.agents/skills/microsoft-docs/SKILL.md`.
- Скиллы взяты из `github/awesome-copilot` и установлены локально в проект. Их рекомендации не отменяют ограничения этого файла на запуск проверок и подключение логики агента.

## Текущий UI

- Использовать SharpConsoleUI и переиспользовать стандартные контролы вместо собственной отрисовки, если они подходят.
- Поддерживать единый аккуратный стиль компонентов.
- `AssistantMessageComponent` содержит отдельные Thinking и Markdown ответа. `ThinkingComponent` использует стандартный `CollapsiblePanel`: появляется только при публичном `TextReasoningContent.Text`, раскрыт во время рассуждения и автоматически сворачивается при начале ответа или завершении. Ручное переключение Enter/Space или кликом имеет приоритет над автоматическим. При ошибке полученное содержимое сохраняется, ошибка показывается отдельно.
- Текст Thinking размещён во внутреннем `ScrollablePanelControl`; высота ограничена `ControlDefaults.ScrollablePanelDefaultUnboundedHeight`, стандартным лимитом вложенных сообщений пользователя. Каждый поступающий reasoning-фрагмент прокручивает внутренний блок вниз; после генерации доступна ручная прокрутка.
- Для reasoning кроме `none` агент запрашивает Responses summary `auto`. Отсутствие summary не создаёт пустого Thinking; `ProtectedData` не отображается. Reasoning и обычный `TextContent` маршрутизируются раздельно. При `none` Thinking скрыт.
- С отправки до окончания запроса футер показывает перед моделью блоковый Knight Rider по `anomalyco/opencode` (`v2/packages/tui/src/ui/spinner.ts`): восемь позиций, движение туда-обратно, шестиступенчатый затухающий хвост и задержки на краях. Кадры заранее вычисляются в бирюзовом цвете, анимируются стандартным `SpinnerTextAnimator`; место под индикатор зарезервировано и в простое. Активность хранится в `StatisticsStore.IsGenerating`. Заголовок Thinking анимирует точки через `SpinnerTextAnimator` с `SpinnerStyle.Dots`, начиная с первого reasoning-фрагмента. При начале ответа, завершении или ошибке аниматор Thinking освобождается, остаётся статический заголовок.
- В idle индикатор футера остаётся видимым как восемь приглушённых точек `⬝⬝⬝⬝⬝⬝⬝⬝`, без анимации.
- Дорабатывать интерфейс небольшими изменениями по моим запросам и скриншотам.

Эти договорённости действуют, пока я явно не изменю их последующим запросом.
