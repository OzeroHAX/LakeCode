# Подход к работе над LakeCode

## Объём изменений

- Делать только то, что запрошено. Не добавлять функции, абстракции, зависимости или рефакторинг «заодно».
- Для текущего UI использовать моки. Не подключать логику кодингового агента без отдельного запроса.
- Разделять UI на отдельные компоненты, а собирать их в `LakeCode.Cli/Program.cs`.
- Сохранять мои изменения в файлах и подстраиваться под них.

## Изучение проекта

- Не искать существующий код и не использовать индексатор, пока я не попрошу: проект начат с пустой кодовой базы.
- Читать конкретные файлы, необходимые для задачи; не проводить широкий аудит проекта.
- Использовать LSP для работы с символами и проверки диагностики.

## Проверка

- Не создавать и не запускать тесты.
- Не запускать приложение, тесты, форматтеры и другие проверки через команды, кроме сборки проекта. Я проверяю приложение сам.
- В конце любой правки перед финальным ответом обязательно выполнить сборку проекта командой `dotnet build LakeCode.Cli/LakeCode.Cli.csproj` из корня репозитория. Ошибки сборки, вызванные правкой, исправить и повторить сборку; в финальном ответе сообщить фактический результат. Если сборка заблокирована окружением, явно указать причину и не утверждать, что компиляция проверена.
- Допустима дополнительная проверка через LSP. Если сервер не работает, честно сообщать об этом.
- Пришедшую позже диагностику LSP учитывать и исправлять ошибки, не запуская приложение.
- Скриншоты и мои сообщения о поведении использовать как основу для дальнейших изменений.

## Взаимодействие

- По ясному запросу сразу вносить изменения, без лишних подтверждений.
- Если область изменения неоднозначна, задавать короткий конкретный вопрос.
- Кратко сообщать, что изменено и что действительно проверено.
- Не выдавать предполагаемый внешний вид или поведение за результат запуска.

## База агента

- Для базы кодингового агента использовать Microsoft Agent Framework (MAF).
- Базовая зависимость: `Microsoft.Agents.AI` версии `1.24.0` в `LakeCode.Cli/LakeCode.Cli.csproj`.
- Основа агента находится в `LakeCode.Cli/Agent/AgentLoop.cs`: MAF с адаптером `Microsoft.Agents.AI.OpenAI` версии `1.24.0`, OpenAI Responses API, endpoint `https://api.wikivibe.ru/v1`. Модель и уровень рассуждения задаются для каждого запроса; начальный выбор — `gpt-6-luna` и `medium`.
- Системный промпт собирает `LakeCode.Cli/Agent/SystemPromptBuilder.cs` из постоянных секций: роль, изучение проекта, работа с инструментами чтения, записи и bash, ограничения проверки, безопасность и формат ответов. В конце добавляется неизменяемый `SystemPromptContext`: рабочий корень, ОС и её версия, архитектуры ОС и процесса. Контекст фиксируется при создании `AgentLoop`; версия .NET, время, hostname, имя пользователя и переменные окружения в промпт не включаются.
- При создании `AgentLoop` в системный промпт напрямую добавляется содержимое `~/.agents/AGENTS.md`, затем `AGENTS.md` из зафиксированного рабочего каталога. Файлы читаются один раз на сессию, перед секцией контекста. Отсутствующие и пустые файлы молча пропускаются; остальные ошибки чтения не скрываются.
- Каталог моделей и их возможностей находится в `LakeCode.Cli/Agent/ModelCatalog.cs`, описание модели — в `LakeCode.Cli/Agent/ModelInfo.cs`. Namespace файлов агента: `LakeCode.Cli.Agent`.
- Ключ получать из переменной окружения `WIKIVIBE_API_KEY`; не хранить ключи в исходниках. `new AgentLoop()` создаёт агент, `RunAsync(message, model, reasoningEffort, cancellationToken)` принимает пользовательский `ChatMessage` и возвращает поток `AgentResponseUpdate`. Текст передаётся как `TextContent`, изображения — как `DataContent` с оригинальными байтами и MIME фактически декодированного формата; уменьшенное превью агенту не отправляется. Допустим запрос только с изображениями, без текста; пустой запрос и изображения для модели без `ModelModality.Image` отклоняются. Один экземпляр хранит одну сессию; запросы выполнять последовательно и полностью читать поток ответа. Уровень передаётся через Responses `ReasoningOptions`, включая строковые значения `xhigh` и `max`.
- Для cache affinity по схеме Codex каждый `AgentLoop` создаёт один UUID на время своей сессии. Он передаётся в JSON Responses как `prompt_cache_key` через `CreateResponseOptions.Patch`, а также в HTTP-заголовках `session-id` и `thread-id` через `CodexSessionHeadersPolicy`. ID сохраняется между сообщениями и продолжениями после инструментов; в системный промпт не добавляется. Схема не меняет хранение истории и не гарантирует cache hit: пересылка идентификаторов и маршрутизация upstream зависят от WikiVibe.
- UI подключён к агенту через `ChatController`. `ModelStore` хранит модель и уровень рассуждения; Shift+Tab в главном окне переключает поддерживаемые моделью уровни. Настройки фиксируются при отправке, изменения во время генерации действуют на следующий запрос. Футер наблюдает сторы; `StatisticsStore` сохраняет последний usage вместе с моделью запроса. Ошибки провайдера и отмена передаются вызывающему коду.
- Инструменты подключены как MAF Function Tools в `AgentLoop`: `read_file`, `list_directory`, `grep`, `write_file`, `edit_file`, `bash`. Каждый находится в своей папке внутри `LakeCode.Cli/Agent/tools`; общие файловые ограничения — в `WorkspaceFiles.cs`. Рабочий корень фиксируется при создании агента. `read_file`, `list_directory` и `grep` могут читать внешние пути только после подтверждения пользователем конкретной папки и её подпапок; разрешения и запреты хранятся в экземпляре `AgentLoop` до `/new` или выхода. Без обработчика подтверждения внешний доступ запрещён. `write_file`, `edit_file` и рабочий каталог `bash` остаются ограничены корнем независимо от разрешений на чтение. Переходы через симлинки запрещены, включая предков внешнего пути. Это проверка путей, не OS sandbox для файловой системы, изменяемой сторонними процессами.
- `read_file` читает UTF-8 с номерами строк и параметрами `startLine`/`lineCount`; предел файла — 1 MiB. `list_directory` возвращает непосредственные записи, до 500 за вызов, с `offset` для следующих страниц. `grep` ищет литерал или regex рекурсивно с маской имени файла, выбором регистра и лимитом до 500 совпадающих строк; timeout regex — 250 мс на строку. Обход пропускает `.git`, `bin`, `obj` и симлинки; бинарные, нечитаемые и слишком большие файлы отмечаются как пропущенные. Вывод ограничен 32 000 символов содержимого с явной отметкой об усечении.
- `write_file(path, content, overwrite = false)` создаёт UTF-8 файл и необходимые родительские каталоги; существующий файл заменяется только при явном `overwrite: true`. `edit_file(path, oldText, newText)` заменяет ровно одно точное совпадение с учётом регистра, пробелов и переводов строк; при отсутствии или неоднозначности совпадения файл не изменяется. Размер результата ограничен 1 MiB. Запись выполняется через временный файл в том же каталоге с последующим переименованием, чтобы отмена до фиксации не оставляла частично записанный файл. Правка сохраняет UTF-8 BOM и переводы строк вне заменяемого фрагмента; при замене существующего файла сохраняются Unix-права.
- `bash(command, workingDirectory = ".")` запускает установленный `bash -c` в каталоге внутри рабочего корня. Возвращает код выхода, stdout и stderr после завершения; ненулевой код помечается `Error:`. stdin закрыт, PTY, фоновые задачи, job ID, polling и отдельный wait-инструмент отсутствуют; команды не должны запускать фоновые или интерактивные процессы. При отмене запроса завершается дерево процесса. stdout и stderr читаются одновременно и продолжают вычитываться после достижения лимита; сохраняется до 16 000 символов каждого потока с отметкой усечения. Bash не является sandbox и имеет OS-права приложения, включая техническую возможность доступа за пределами рабочего корня. Ограничения проекта на запуск проверок продолжают действовать.
- TPS в футере вычисляется после успешного завершения потока: `OutputTokenCount / секунды от первого непустого TextReasoningContent или TextContent до завершения`. Reasoning уже входит в выходные токены и отдельно не прибавляется. Пока идёт запрос, сохраняется предыдущий TPS; без usage или наблюдаемого первого токена отображается `— tok/s`. Если провайдер не отдаёт reasoning, отсчёт начинается с первого текстового фрагмента ответа.
- Для работы с MAF читать `.agents/skills/microsoft-agent-framework/SKILL.md` и его `references/dotnet.md`; для поиска актуальной официальной документации использовать `.agents/skills/microsoft-docs/SKILL.md`.
- Скиллы взяты из `github/awesome-copilot` и установлены локально в проект. Их рекомендации не отменяют ограничения этого файла на запуск проверок и подключение логики агента.

## Текущий UI

- Использовать SharpConsoleUI и переиспользовать стандартные контролы вместо собственной отрисовки, если они подходят.
- Поддерживать единый аккуратный стиль компонентов.
- `AssistantMessageComponent` содержит отдельные Thinking и Markdown ответа. `ThinkingComponent` использует стандартный `CollapsiblePanel`: появляется только при публичном `TextReasoningContent.Text`, раскрыт во время рассуждения и автоматически сворачивается при начале ответа или завершении. Ручное переключение Enter/Space или кликом имеет приоритет над автоматическим. При ошибке полученное содержимое сохраняется, ошибка показывается отдельно.
- `ToolCallGroupComponent` группирует последовательные вызовы одного инструмента: `Read N files`, `List N directories`, `Grep N searches`, `Write N files`, `Edit N files`, `Run N commands`. Другой инструмент или текст ответа начинает новую группу. Группы и отдельные вызовы свёрнуты по умолчанию; раскрытие показывает путь/запрос/команду, аргументы, статус и результат в ограниченном прокручиваемом блоке. Порядок текста и групп сохраняется. Реальные начало и завершение вызова приходят из MAF function middleware через `AgentLoop.ToolCallUpdated`; `ChatController` обновляет UI через очередь UI-потока. Ошибки и отмена показаны отдельно от успешных результатов; вызовы без результата при окончании запроса помечаются прерванными.
- Запрос доступа к внешней папке отображается компонентом `ExternalReadPermissionComponent` прямо в панели соответствующего вызова тула, без модального окна. Группа и вызов автоматически раскрываются; показаны абсолютные путь и папка, область read-only и срок разрешения. Стандартный `ListControl` предлагает «Запретить до конца сессии» (выбран по умолчанию) и «Разрешить до конца сессии»; ↑↓ выбирают, Enter или активация мышью подтверждает, Esc отклоняет только текущий вызов без сохранения выбора. До решения вызов ожидает и не читает содержимое. Ожидания сериализуются; следующий вызов использует сохранённый выбор. Отмена запроса прекращает ожидание, убирает обработчик клавиш и не сохраняет выбор. Решения относятся к конкретной папке и её потомкам, но не к соседям или родителям; при пересечении действует наиболее конкретное ранее выбранное правило.
- Список вариантов подтверждения не задаёт фиксированный `Height`: стандартный `ListControl` рассчитывает высоту для двух пунктов (`MaxVisibleItems = 2`) с учётом отступов, чтобы оба варианта были видны.
- В деталях инструментов аргументы отображаются отдельными строками `имя: значение`, без JSON-экранирования; bash-команда остаётся в заголовке и не дублируется в аргументах. Строковый результат MAF, включая `JsonElement` типа String, показывается как обычный текст с настоящими переносами строк и Unicode; исходный результат для агента не изменяется.
- Успешные `edit_file` и `write_file` показывают цветной diff содержимого до и после зафиксированной записи: красные удалённые и зелёные добавленные строки, старые/новые номера, по три строки контекста, путь и счётчики изменений. Общие начальные и конечные строки исключаются из изменённого блока; превью ограничено 32 000 символов с явной отметкой усечения. При недоступном исходном тексте перезапись сохраняет прежнее поведение, UI сообщает причину отсутствия diff. Полные `oldText`, `newText` и `content` в аргументах не дублируются. Для агента результат инструмента остаётся прежней строкой; снимки изменений передаются отдельно в `ToolCallUpdate.FileChange` только после успешной записи.
- Текст Thinking размещён во внутреннем `ScrollablePanelControl`; высота ограничена `ControlDefaults.ScrollablePanelDefaultUnboundedHeight`, стандартным лимитом вложенных сообщений пользователя. Каждый поступающий reasoning-фрагмент прокручивает внутренний блок вниз; после генерации доступна ручная прокрутка.
- Для reasoning кроме `none` агент запрашивает Responses summary `auto`. Отсутствие summary не создаёт пустого Thinking; `ProtectedData` не отображается. Reasoning и обычный `TextContent` маршрутизируются раздельно. При `none` Thinking скрыт.
- С отправки до окончания запроса футер показывает перед моделью блоковый Knight Rider по `anomalyco/opencode` (`v2/packages/tui/src/ui/spinner.ts`): восемь позиций, движение туда-обратно, шестиступенчатый затухающий хвост и задержки на краях. Кадры заранее вычисляются в бирюзовом цвете, анимируются стандартным `SpinnerTextAnimator`; место под индикатор зарезервировано и в простое. Активность хранится в `StatisticsStore.IsGenerating`. Заголовок Thinking анимирует точки через `SpinnerTextAnimator` с `SpinnerStyle.Dots`, начиная с первого reasoning-фрагмента. При начале ответа, завершении или ошибке аниматор Thinking освобождается, остаётся статический заголовок.
- В idle индикатор футера остаётся видимым как восемь приглушённых точек `⬝⬝⬝⬝⬝⬝⬝⬝`, без анимации.
- В футере отображается реальный текущий рабочий каталог, передаваемый из `Environment.CurrentDirectory` в `Program.cs`, вместо фиксированной строки `./LakeCode`.
- Основная строка футера показывает входные токены относительно контекстного окна без процента и надписи `cache hit`; сырой счётчик `cached` сохраняется в строке usage ниже.
- Под основной строкой футера выводятся точные значения последнего usage из MAF: `input`, `cached`, `output`, `reasoning`, `total`, без сокращений и округления. Отсутствующее значение показано как `null`, а не ноль; это значения `UsageDetails`, не сырой JSON провайдера.
- Поле ввода поддерживает изображения как отдельные вложения черновика, не как символы `PromptControl`. `Ctrl+V` при фокусе в редакторе читает изображение или текст; `Ctrl+O` и кнопка открывают стандартный file picker. Чтение изображений из clipboard реализовано для локального Linux: `wl-paste` (Wayland) или `xclip` (X11), бинарный stdout, ограничение времени 5 секунд. Через SSH использовать вставку текста средствами терминала или выбор файла на сервере; на других ОС системное чтение clipboard остаётся текстовым, изображения добавляются через file picker. Поддерживаются PNG, JPEG и WebP; до 4 вложений, до 8 MiB каждое и 24 MiB суммарно, до 8192 пикселей по стороне и 16 мегапикселей. Превью декодируется только этими тремя декодерами ImageSharp, один кадр без загрузки метаданных; оригинальные байты, включая имеющиеся метаданные, хранятся отдельно и отправляются агенту без перекодирования. Стандартный `CollapsiblePanel` показывает имя, размеры и объём; раскрытие содержит `ImageControl` и кнопку удаления. Список ограничен по высоте и прокручивается. Чтение не блокирует UI, ошибки сохраняют черновик; `/new` отменяет незавершённую вставку и очищает вложения. При отправке текст и снимок списка вложений фиксируются до очистки черновика и передаются как один пользовательский `ChatMessage` через MAF в Responses API; можно отправить изображения без текста. В истории UI изображения остаются раскрываемыми превью без удаления. Если выбранная модель не поддерживает изображения, отправка блокируется с пояснением и черновик сохраняется. Во время чтения отправка также заблокирована.
